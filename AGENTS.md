# OpenPrintLab assistant instructions

Build useful, understandable models; never imply that generated means printable.

- Read `docs/decisions.md`, `models/catalog.json` and the relevant recipe first.
- Read `docs/structural-design.md` before classifying a request involving loads,
  joints, glazing or mounting. It is the canonical eligibility/evidence policy.
- Use `.github/skills/create-printable-model/SKILL.md` for authoring/customization.
- For richer editable templates, read `docs/template-lab.md`. The optional
  CadQuery backend is approved under milestone 003; keep it opt-in.
- Discover using `python -m tools.cli templates` and `template ID`. Interpret
  natural-language requests in the assistant, not a fabricated CLI parser.
- Use `customize ID --variant NEW-NAME --set key=value` for non-destructive
  results. Return the actual preview URI/local lab URL and STL/STEP/report paths.
  Never replace a prior variant or the original to satisfy a revision request.
- Lengths are mm. Validate all parameters, including finite values, counts and
  relationships. Do not bypass the limits with scale transforms.
- Core tools: `python -m tools.cli list`, `parameters MODEL`, `check MODEL`,
  `build MODEL --set name=value --output build/variant`.
- Keep generated files in `build/` for one-off variants. Change defaults only
  when requested. Default exports are regenerated by `python -m tools.release`.
- Test with `python -m unittest discover -s tests -v`, then
  `python -m tools.release --check` and `python -m tools.site`.
- For UI changes run the browser checks documented in README.
- Never connect to a printer, send G-code, or supply machine-ready G-code.
- Initial printer is Bambu Lab **P2S**, not P1S. Do not assume AMS ownership.
- Never invent slice times, filament usage, successful prints, photos or evidence.
  Reports explicitly keep slicer_checked and physical_print_tested false.
- Preserve model passport version, variant ID, source hashes and STL hash.
  Review model-version changes when changing design source; fresh variants never
  inherit slicer/physical evidence. Suggested recipes are not actual settings.
- Use the public print-result issue form for real observations, including
  failures; never automatically promote user-submitted claims into validation.
- The 003 plan authorizes the bounded optional CadQuery templates, not a full
  migration, arbitrary imported model editing or paid decorative AI generation.
  Fonts/text templates and additional providers remain deferred.
- For setup advice, call `guidance` / `variant_guidance`; ask for missing actual
  printer/nozzle/plate/material/use. Unsupported setups have no tested profile.
- Keep suggestions separate from verified facts. Users select actual
  printer/nozzle/plate/filament presets and inspect their own slices.
- Follow the canonical guide's hard exclusions and hazard escalation. Bounded
  non-safety-critical decorative prototypes are eligible for custom engineering,
  not automatically safe or impossible because they lack physical evidence.
  Keep the explicit "not validated for hanging/load use" state and full handoff.
- Frames/assemblies are not named templates. An assistant may author reviewed
  task-specific CAD in an authorized workspace, using compatible shared utilities
  and preserving originals. Label custom work honestly; do not extend CLI/MCP
  capabilities, template allowed uses or safety claims to make it look supported.
- Reuse shared catalog/build tools across CLI, site and MCP.
- `models/`, including Python design recipes, and `docs/` are CC BY 4.0.
  `tools/`, tests, website code and assistant integrations are MIT.
- Do not add dependencies unless a required capability justifies them.
